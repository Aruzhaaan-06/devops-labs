# Зертханалық жұмыс 4, 2-бөлім - материал 08

**ВКТУ · Есімханова Аружан Түсіпханқызы · 25-ИСТК-2о**

## Мақсаты және API келісімшарты

Жоба атауын өзгертуді екі сақтау режимінде іске асыру, өзгерістерді PR арқылы тексеру және `v0.1.0` шығарылымын жариялау.

`PUT /api/projects/{id}` сұрауының денесі: `{ "name": "Жаңа атау" }`.

| Жауап | Шарты |
|---|---|
| 200 | Жоба атауы өзгертілді; жауапта id, name, createdAt қайтарылады |
| 400 | name жоқ, null, бос, тек бос орындардан тұрады немесе 100 таңбадан ұзын |
| 404 | Жоба табылмады; атау басқа жобада қолданылса да, осы жауап басым |
| 409 | Атауды басқа жоба қолданып отыр |

Бұрынғы атаумен қайта жіберілген PUT сұрауы 200 қайтарады. Регистр ескеріледі; атау автоматты түрде қысқартылмайды. Жоба идентификаторы, құрылған уақыты және оған тиесілі тапсырмалар өзгермейді.

## Іске асыру

`ProjectsController → ProjectService → IProjectRepository`. InMemory нұсқасы `lock (store.Sync)` ішінде жазбаның көшірмесін ауыстырады. PostgreSQL нұсқасы `$1`, `$2` параметрлері бар UPDATE ... RETURNING сұрауын орындайды. Атау бір уақытта өзгертілгенде де бірегей болып қалуы тиіс: InMemory тексеруі сол lock ішінде, SQL нұсқасында UNIQUE шектеуі бар. Қақтығыс `ProjectNameConflictException` арқылы HTTP 409 жауабына айналады; SQL қатесінің ішкі деректері клиентке берілмейді. Бұрыннан бар POST әрекетінің бәсекелес сұрауларға қатысты мінез-құлқы осы жұмыста өзгертілмейді.

## Тексеру

```powershell
docker compose up -d --wait db
dotnet test DemoApi.slnx
docker compose up -d --build --wait
curl.exe http://localhost:8088/health/ready
```

Бірінші `dotnet test` пәрмені әдепкі InMemory режимін тексереді. SQL тексеруі үшін `Storage=Postgres` және `ConnectionStrings__Db` айнымалыларын жергілікті тест дерекқорына бағыттау қажет; парольді Git-ке, есепке немесе терминал журналына енгізуге болмайды. Нақты орындалған тексерулер кейін evidence каталогында көрсетіледі.

Postman жинағына «Лабораторная 4 - переименование проекта» қалтасы қосылды: тәуелсіз екі жоба жасалады, 200/400/404/409 жауаптары, қайталанатын PUT және қате сұраудан кейін деректердің сақталуы тексеріледі; соңында тек осы қалта жасаған екі жоба жойылады. Бұрынғы қалталар сақталған.

## Репозиторийді баптау

`.github/pull_request_template.md` авторға іске қосу, тесттер, құпия деректер мен құжаттаманы тексеруді еске салады. `.github/dependabot.yml` NuGet, Docker және GitHub Actions тәуелділіктерін апта сайын тексеруге бапталған. Бұл файлдың болуы барлық жаңартулардың іске қосылғанын немесе осалдықтардың жоқтығын дәлелдемейді. CI келесі 09 тапсырмада қосылады.

CODEOWNERS барлық файлдарға `temirkhanerbolatovich-coder` аккаунтын тағайындайды. main үшін code owner мақұлдауы міндетті; тікелей push, force-push және тармақты жоюға қойылған шектеулер сақталады.
