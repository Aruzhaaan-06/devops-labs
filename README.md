# DemoApi — учебный сервис проектов и задач

REST API на ASP.NET Core / .NET 10: создание проектов и задач, фильтрация, изменение задач, переходы статусов и статистика проекта. Сервис отвечает JSON; Swagger и Postman используются для работы с API.

Реализована обязательная функция лабораторной 1: `GET /api/projects/{id}/stats`. Сохранены исходные операции API и два варианта хранения: InMemory и PostgreSQL. Сохранённые результаты подтверждают 24 успешных теста в режиме InMemory; запуск PostgreSQL для новой функции предстоит в лабораторной 3. Публикация репозитория на GitHub пока не подтверждена. Docker, CI/CD и стек мониторинга на данном этапе не настроены.

## Требования и запуск

- Windows с .NET 10 SDK; для отладки и Test Explorer — Visual Studio 2026 с компонентом «ASP.NET и разработка веб-приложений».
- Postman или браузер для запросов. Для вспомогательного сценария проверки нужен PowerShell 7.
- Для текущего InMemory-режима отдельная база данных не нужна.

Откройте `DemoApi.slnx` в Visual Studio, выберите проект `DemoApi` и профиль `http`, затем F5. Либо из корня репозитория:

```powershell
dotnet restore DemoApi.slnx
dotnet run --project src/DemoApi/DemoApi.csproj --launch-profile http
```

Текущий адрес — [http://localhost:8088](http://localhost:8088). В этой рабочей среде учебный порт 8080 занят Oracle, поэтому профиль запуска, файл запросов и коллекция используют 8088. Для другой среды порт можно поменять в `src/DemoApi/Properties/launchSettings.json`; одновременно обновите `@host` в `DemoApi.http` и `baseUrl` в коллекции Postman. Профиль `http` включает окружение Development.

| Адрес | Назначение |
|---|---|
| `/swagger` | Описание API и ручные запросы, только Development |
| `/openapi/v1.json` | Контракт OpenAPI, только Development |
| `/api/projects`, `/api/tasks` | Проекты и задачи |
| `/api/projects/{id}/stats` | Сводка задач проекта; отсутствующий проект — 404 |
| `/health/live`, `/health/ready` | Жизнеспособность и готовность |
| `/metrics` | Метрики приложения |

Импортируйте `postman/demo-api.postman_collection.json` в Postman; коллекция называется `demo-api`, переменная `baseUrl` по умолчанию равна `http://localhost:8088`. Запросы также доступны в `src/DemoApi/DemoApi.http`. Используйте идентификаторы из ответов создания; пример с id=1 подходит только при наличии такого проекта.

## Конфигурация и данные

`appsettings.json` задаёт общие параметры, `appsettings.Development.json` переопределяет их в Development, переменные окружения могут переопределить оба файла. `Storage=InMemory` выбран по умолчанию: один `InMemoryStore` на процесс, данные полностью теряются при его завершении. Строка консоли «Хранилище: в памяти» подтверждает фактический режим.

Для будущего SQL-режима задаются `Storage=Postgres` и `ConnectionStrings__Db` через безопасную конфигурацию окружения. При старте SQL-режим создаёт схему; подключение требует работающего PostgreSQL и соответствующих прав. Учётные данные не следует помещать в отчёт или публичный репозиторий.

Статусы допускают Todo ↔ InProgress ↔ Done и сохранение того же статуса; Todo ↔ Done напрямую возвращает 409. Статистика считает только задачи выбранного проекта. `overdue` — срок строго раньше сегодняшней даты UTC и статус не Done; null, сегодняшний срок и завершённые задачи исключаются. Обе реализации используют одну границу UTC, SQL передаёт её параметром вместо зависимости от часового пояса БД.

Дополнительное правило лабораторной о запрете создания задач с прошедшим сроком пока не заявляется выполненным; основной чек-лист и результаты 24 тестов относятся к обязательной функции.

## Проверка

Перед пересборкой остановите локальный экземпляр приложения/отладку, чтобы Windows не удерживала DLL. Из корня репозитория:

```powershell
$env:Storage = 'InMemory'
dotnet test DemoApi.slnx --logger "trx;LogFileName=lab01-current.trx" --results-directory evidence/lab01/current
Remove-Item Env:Storage
```

В Visual Studio: Test → Test Explorer → Run All. Ожидается 24 случая: 7 юнит и 17 интеграционных. Интеграционные тесты создают API через `WebApplicationFactory<Program>` и не требуют отдельно запущенного сервера. Для скриншота сдачи нужен фактический Test Explorer.

Сохранённые доказательства от 22 октября 2026 года: `evidence/lab01/baseline/lab01-baseline.trx` — 22/22 до добавления функции; `evidence/lab01/required-24/lab01-required-24.trx` — 24/24 после неё, ошибок и пропущенных тестов нет. Это результаты записанных запусков, а не обещание для изменённой версии.

Для проверки уже запущенного API:

```powershell
pwsh -File scripts/verify-lab01.ps1 -Phase All -BaseUrl http://localhost:8088
```

Сценарий выполняет реальные HTTP-запросы, создаёт собственные проекты, проверяет ответы и по умолчанию удаляет только созданные им проекты; `-KeepData` сохраняет их для демонстрации. Сервер он не запускает и не перезапускает. Доказательства записываются в новый подкаталог `evidence/lab01/`. Сохранённый `20261021T192942693Z-all-2e4aa0e5/http-evidence.json` содержит успешную проверку 21 запроса на 8088 без дополнительного правила. Скрипт дополняет, но не заменяет обязательные скриншоты Postman, отладчика и Test Explorer.
