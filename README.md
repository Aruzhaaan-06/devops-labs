# DemoApi — учебный сервис проектов и задач

REST API на ASP.NET Core / .NET 10: создание проектов и задач, фильтрация, изменение задач, переходы статусов и статистика проекта. Сервис отвечает JSON; Swagger и Postman используются для работы с API.

Реализованы статистика проекта `GET /api/projects/{id}/stats` и дополнительный запрет создания задачи с прошедшим сроком. Сохранены исходные операции API и два варианта хранения: InMemory и PostgreSQL. В обязательном этапе прошли 24 теста, после дополнительного правила — 28; запуск PostgreSQL для новой функции предстоит в лабораторной 3. Публичный репозиторий: [Timoha-R/devops-labs](https://github.com/Timoha-R/devops-labs). [Тег lab01-required-24](https://github.com/Timoha-R/devops-labs/tree/lab01-required-24) сохраняет обязательный этап на коммите `f93b123`. Docker, CI/CD и стек мониторинга на данном этапе не настроены.

Для полного комплекта сдачи ещё нужны настоящие скриншоты коллекции Postman и Test Explorer, а также ручная пошаговая отладка F9/F10/F11 с Locals и Call Stack. Захват интерфейса завершился тайм-аутом; имеющиеся цепочки установлены чтением кода, а HTTP-поведение проверено запросами. Выполнение этих UI-пунктов пока не подтверждено.

## Требования и запуск

- Windows с .NET 10 SDK; для отладки и Test Explorer — Visual Studio 2026 с компонентом «ASP.NET и разработка веб-приложений».
- Postman или браузер для запросов. Для вспомогательного сценария проверки нужен PowerShell 7.
- Для текущего InMemory-режима отдельная база данных не нужна.

Откройте `DemoApi.slnx` в Visual Studio, выберите проект `DemoApi` и профиль `http`, затем F5. Либо из корня репозитория:

```powershell
dotnet restore DemoApi.slnx
dotnet run --project src/DemoApi/DemoApi.csproj --launch-profile http
```

Текущий адрес — [http://localhost:8088](http://localhost:8088). В этой рабочей среде учебный порт 8080 занят Oracle, поэтому профиль запуска, файл запросов и коллекция используют 8088. Для другой среды порт можно поменять в `src/DemoApi/Properties/launchSettings.json`; одновременно обновите `@host` в `DemoApi.http` и `baseUrl` в коллекции Postman. Профиль `http` включает окружение Development.

| Адрес | Назначение |
|---|---|
| `/swagger` | Описание API и ручные запросы, только Development |
| `/openapi/v1.json` | Контракт OpenAPI, только Development |
| `/api/projects`, `/api/tasks` | Проекты и задачи |
| `/api/projects/{id}/stats` | Сводка задач проекта; отсутствующий проект — 404 |
| `/health/live`, `/health/ready` | Жизнеспособность и готовность |
| `/metrics` | Метрики приложения |

Импортируйте `postman/demo-api.postman_collection.json` в Postman; коллекция называется `demo-api`, переменная `baseUrl` по умолчанию равна `http://localhost:8088`. Запросы также доступны в `src/DemoApi/DemoApi.http`. Используйте идентификаторы из ответов создания; пример с id=1 подходит только при наличии такого проекта.

## Конфигурация и данные

`appsettings.json` задаёт общие параметры, `appsettings.Development.json` переопределяет их в Development, переменные окружения могут переопределить оба файла. `Storage=InMemory` выбран по умолчанию: один `InMemoryStore` на процесс, данные полностью теряются при его завершении. Строка консоли «Хранилище: в памяти» подтверждает фактический режим.

Для будущего SQL-режима задаются `Storage=Postgres` и `ConnectionStrings__Db` через безопасную конфигурацию окружения. При старте SQL-режим создаёт схему; подключение требует работающего PostgreSQL и соответствующих прав. Учётные данные не следует помещать в отчёт или публичный репозиторий.

Статусы допускают Todo ↔ InProgress ↔ Done и сохранение того же статуса; Todo ↔ Done напрямую возвращает 409. Статистика считает только задачи выбранного проекта. `overdue` — срок строго раньше сегодняшней даты UTC и статус не Done; null, сегодняшний срок и завершённые задачи исключаются. Обе реализации используют одну границу UTC, SQL передаёт её параметром вместо зависимости от часового пояса БД.

При POST задачи DueDate раньше сегодняшней даты UTC возвращает 400 с `errors.DueDate`; задача не создаётся. Сегодняшний срок, будущий срок и null допустимы. Проверка находится в `TasksController.Create` и формирует стандартный ValidationProblemDetails. Она действует только при создании: PUT может установить прошедший срок существующей задаче, в том числе для проверки overdue.

## Проверка

Перед пересборкой остановите локальный экземпляр приложения/отладку, чтобы Windows не удерживала DLL. Из корня репозитория:

```powershell
$env:Storage = 'InMemory'
dotnet test DemoApi.slnx --logger "trx;LogFileName=lab01-current.trx" --results-directory evidence/lab01/current
Remove-Item Env:Storage
```

В Visual Studio: Test → Test Explorer → Run All. В итоговой версии ожидается 28 случаев: 7 юнит и 21 интеграционный. На теге `lab01-required-24` — 24 случая, 7 юнит и 17 интеграционных. Интеграционные тесты создают API через `WebApplicationFactory<Program>` и не требуют отдельно запущенного сервера. Для скриншота сдачи нужен фактический Test Explorer; консольный запуск его не заменяет.

Сохранённые сводки запусков от 22 октября 2026 года: `evidence/lab01/baseline/summary.json` — 22/22 до добавления функции; `evidence/lab01/required-24/summary.json` — 24/24 после неё; `evidence/lab01/optional-28/summary.json` — 28/28 с дополнительным правилом. Ошибок и пропущенных тестов нет. Сводки получены из реальных TRX; оригиналы сохраняются локально, а сведения о пользователе и машине исключены из публикуемых сводок. Это результаты записанных запусков, а не обещание для изменённой версии.

Для проверки уже запущенного API:

```powershell
pwsh -File scripts/verify-lab01.ps1 -Phase All -BaseUrl http://localhost:8088 -IncludePastDueValidation
```

Сценарий выполняет реальные HTTP-запросы, создаёт собственные проекты, проверяет ответы и по умолчанию удаляет только созданные им проекты; `-KeepData` сохраняет их для демонстрации. Сервер он не запускает и не перезапускает. Доказательства записываются в новый подкаталог `evidence/lab01/`. Итоговый `20261021T194046965Z-all-7024bbae/http-evidence.json` подтверждает 23 успешных запроса с дополнительным правилом. Postman CLI выполнил обязательную коллекцию:22 запроса/67 проверок; итоговую:24 запроса/73 проверки, без ошибок. Логи — `evidence/lab01/postman-required/console.txt` и `evidence/lab01/postman-final/console.txt`; эти локальные запуски не означают публикацию результатов в облако Postman.

Реальный перезапуск процесса проверен отдельно: до него было4 проекта, после — пустой список; ответы сохранены в `evidence/lab01/restart/before.json` и `after.json`. Скрипт и CLI дополняют, но не заменяют обязательные скриншоты Postman, отладчика и Test Explorer.
